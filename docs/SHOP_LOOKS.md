# Shop Looks

A cosmetic interior preset system for the tailor shop: recolours the upper wall,
wainscot panelling, floor, rugs and curtains as one bundle. Purely visual today —
ready to become a reputation-gated cosmetic purchase once a menu is wired up for it.

## How it works

- `data/scripts/shop_look.gd` (`ShopLook`, a `Resource`) holds an id, display name,
  description, `price`/`reputation_required` (same pricing language as
  `globals/upgrades.gd`), and one `ShopLookSlot` per surface: `wall`, `wainscot`,
  `floor`, `rug`, `drape`.
- `data/scripts/shop_look_slot.gd` (`ShopLookSlot`) is a texture set (albedo / normal /
  roughness) plus `tint`, `uv_scale`, `roughness` and `normal_scale`.
- `scenes/world/shop_look_applier.gd` (`ShopLookApplier`, a `Node`) does the work: it
  walks every `MeshInstance3D` under the shop and, for each surface whose *baked*
  material name matches a slot, builds (and caches) a shared `StandardMaterial3D` from
  the current look and sets it as a `surface_override_material`. Matching is by material
  name, not node path or mesh name, so it works unchanged on any town-kit shop export
  that uses these names.

## The slot / material-name table

| Slot | v7 material name | v6 material name (alias) | Baked UV scale |
|---|---|---|---|
| wall (upper wall) | `InWall` | `inwall_sage` | 2 m per UV tile |
| wainscot (dado panelling) | `Wainscot` | `inwall_green` | 2 m per tile |
| floor | `Floor` | `floor_planks` | 2 m per tile |
| rug (rectangular rugs) | `Rug` | `rug_tex_green` | 0..1 across the rug (non-tiling) |
| drape (curtains) | `Drape` | `drape_green` | 1 m per tile |

Both names are checked (`ShopLookApplier.SLOT_ALIASES`), so one look works on the old v6
export and the new v7 export without changes. The rug slot's UV scale is always forced
to 1.0 by the applier — its UVs already span the whole (non-tiling) rug image, so
scaling it would visibly break the rug's pattern.

A slot's `uv_scale` corrects for a texture authored at a different density than the
mesh's bake: e.g. a wallpaper authored at 1 m/tile needs `uv_scale = 2.0` on the wall
slot (baked at 2 m/tile) to actually tile at 1 m. Textures already authored to match the
bake (the wood/paint/plaster/floor/parquet/velvet sets) use the default `1.0`.

## Presets

Six looks ship in `data/shop_looks/`, generated by `tools/build_shop_looks.gd` (re-run it
to reset them to these defaults — they're then hand-edited in the Inspector):

| id | display name | price | reputation | notes |
|---|---|---|---|---|
| `sage_panel` | Sage & Panel | 0 | 0 | free from the start |
| `forest_green` | Forest Green | 0 | 0 | full-height green board panelling |
| `oxblood` | Oxblood | 120 | 40 | deep red panelling + parquet |
| `cream_walnut` | Cream & Walnut | 260 | 40 | pale plaster + walnut wainscot |
| `navy_atelier` | Navy Atelier | 320 | 120 | striped wallpaper + navy panelling |
| `plum_damask` | Plum Damask | 480 | 260 | damask wallpaper + plum panelling |

Textures live at `res://assets/textures/shop_looks/<set>_{albedo,normal,rough}.png`.
`wallpaper_stripe`, `wallpaper_damask`, `rug_navy`, `rug_camel` and `rug_plum` are
**placeholders** (copies of `paint_*` / `rug_green_*`) until a dedicated texture set is
dropped in under those exact filenames — nothing else needs to change when that happens.

## Adding a look

1. Drop a new texture set at `res://assets/textures/shop_looks/<set>_{albedo,normal,rough}.png`
   (or reuse an existing set).
2. Add an entry to the `presets` dictionary in `tools/build_shop_looks.gd` (id, display
   name, description, price, reputation, and a `_slot(...)` call per surface), then
   re-run it:
   ```
   godot --headless --path . --script res://tools/build_shop_looks.gd
   ```
3. If it should ship by default, add its id to `ShopLookApplier.DEFAULT_LOOK_ORDER`
   (this fixes the index order — `fern_damask` is the default and stays index 0).
4. `godot --headless --path . --script res://tools/test_shop_looks.gd` and
   `godot --path . --script res://tools/shot_shop_looks.gd` (inspect `.dev/looks/`) to
   check it.

## Runtime

`ShopLookApplier.attach(root)` — called once from `main.gd`, right next to
`ShopDoor.attach_all` — finds the shop (a node named `tailor_shop_v*` anywhere under
`root`), adds a `ShopLookApplier` under it with the default look list, and applies the
saved/current look. Public API: `apply(index)`, `apply_id(id)`, `next()`, `previous()`,
`get_look()`, `matched_slots()`.

In debug builds (`OS.is_debug_build()`), **F4** cycles to the next look and prints its
name (F2 and F3 are already used by other debug tools).

## Persistence

`ShopLookApplier` implements `save_state()` / `load_state()`, so `SaveManager`'s generic
station scan (`_capture_stations` / `_restore_stations` in `globals/save_manager.gd`)
picks it up automatically — no changes to the save code were needed. A save stores the
current look id and the list of owned look ids (looks with `price == 0` are owned by
default).

## Future: cosmetic upgrade menu

Nothing here is wired into the shop or phone UI yet. `ShopLook.price` /
`reputation_required` and `ShopLookApplier.is_owned()` / `owned_ids()` are ready for a
future phone menu (in the style of `globals/upgrades.gd`) that lets the player buy a look
once their reputation tier and money allow it, then call `apply_id()`.

## Rugs and wallpapers (round 6)

- **Three rug slots.** `rug` (rectangular, material `Rug`), `rug_round` (`RugRound`) and
  `rug_runner` (`RugRunner`). Each shape has its own image, so one design is never
  stretched over a round rug and a runner. Only the v7 shop has the round and runner
  surfaces; they are optional slots, so v6 does not warn about them.
- **Rugs are drawn, not generated.** `IMPORT/town_kit/textures/_src/make_rugs.py` draws one
  colour family as rect + round + runner (`rug_<family>[_round|_runner]_albedo.png`):
  chunky borders, scallops, a few big flowers / dots / diamonds, cream fringe. To add a
  family, add a row to `FAMILIES` and re-run it; it also writes the copies in
  `assets/textures/shop_looks/`. The earlier diffusion rugs were too detailed and rustic
  for the game (kept in `textures/_backup_rugs_v1/`).
- **Wallpapers** are greyscale tint sets at 1 m per tile (`uv_scale` 2.0 on the wall slot).
  `wallpaper_damask` and the paper ground of `wallpaper_stripe` come from the diffusion
  pipeline; `wallpaper_floral`, `wallpaper_trellis` and `wallpaper_fern` are drawn by
  `_src/make_wallpapers.py` because diffusion made them too faint or crooked.
- **Looks:** `tools/build_shop_looks.gd` takes a rug family name per look and fills the
  three rug slots from it. Eleven looks ship: Sage & Panel, Forest Green, Oxblood, Cream &
  Walnut, Navy Atelier, Plum Damask, Fern Damask, Mint Trellis, Olive Fern, Sage Blossom,
  Chestnut & Toffee.
